# 通用源码审查知识

先理解业务操作和受保护资产，再识别输入来源、信任边界与实际控制点。将推导出的约束写成可用源码回答的问题。以下方向用于启发，可按项目实际情况取舍。

- **身份认证与身份来源**。敏感操作由谁发起？身份来自经过验证的服务端上下文、会话或凭证，还是由客户端声明？哪些服务端分支执行同一操作？
- **授权与资源归属**。调用方是否有权操作该资源？核对角色、租户、资源归属以及共享、管理员和批量操作的政策差异。
- **数据完整性**。区分客户端提供的标识与服务端权威数据。金额、数量、权限、所有者和派生属性是否由可信来源确定或重新计算？
- **业务状态与并发**。核对状态转换、前置条件、幂等性和失败处理。考虑重试、重复提交或并发更新时业务约束是否仍成立。
- **输入及敏感操作**。审查进入命令、动态执行、数据库、网络、文件、HTML 或反序列化接口的数据。定位校验、固定目标、参数化和隔离边界。
- **敏感信息与隐私**。检查凭据、个人信息和内部标识的保存、日志、返回和跨边界处理。结合调用者权限确认所需的最小数据。

单个静态模式或未看到某个检查只提供阅读线索。区分文档要求、合理推导的业务约束和源码中已证实的行为。
