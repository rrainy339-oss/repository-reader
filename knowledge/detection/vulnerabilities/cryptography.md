# 密码学用途、完整性与密钥管理

涉及口令、签名、加密存储、Token、随机数或密钥生命周期时。

## 安全属性与成立条件

控制应满足其真实目标，例如保护机密性、验证完整性或产生不可预测的凭据。弱控制的判定依赖实际算法、参数、密钥来源和保护对象。校验和与保密加密是不同需求。

## 源码调查

从调用点确认算法与 API 参数如何选择，密钥由谁生成、读取、轮换、撤销和访问。检查加密模式需要的 nonce/IV 约束、认证标签或签名的实际验证，以及验证失败时的行为。身份凭据还需结合会话用途、签发方和过期条件。避免按算法字符串直接跨项目定性。

## 控制、证据与误报

对照例使用经过核实的密码学随机源生成安全令牌，口令采用适用的口令派生方案，完整性验证失败时拒绝采纳数据。算法与密钥约束以目标 Node 版本和已采用的规范为准。引用真实用途、参数、密钥来源和消费分支。非安全用途的哈希、测试向量、被安全封装覆盖的默认值都可构成反证。

## 保护目标与消费时点

从数据访问或授权决策反查签名、密文、摘要或者随机值。定位算法参数、密钥来源、轮换映射和错误路径。用于校验内容相等的摘要不表示在认证调用者。签名覆盖的实际字节及上下文由格式和解析路径决定。AEAD 解密中，Node.js 的 `decipher.final()` 可能在标签校验失败时抛错。要核对流式接收器是否在最终认证前已把输出写入业务存储、响应或命令处理。随机值用于令牌、nonce、幂等键或仅作界面标识时，需求不同。读取生成器实际调用与使用范围。

例如，消息适配器先完整验证和解密、再解析通过认证的内容，并且失败时不会发布主体或触发动作。若密钥由配置注入，只凭变量名或算法字符串无法判断线上密钥质量与隔离。可记录源码只接受密钥句柄、没有明文泄露路径，轮换和访问范围留作部署证据。`timingSafeEqual` 只涵盖调用本身的比较，输入长度检查、异常与外层处理仍需阅读。
